# 本地农历与生活指数（1.12.0）

主界面右上角显示“生活指数”卡片：第一行依次是衣服图标与穿衣指数、太阳
图标与紫外线指数；第二行是笑脸图标与感冒指数、跑步图标与运动指数。
每个图标后直接显示 `：舒适` 等简短结果。四项来自一次心知天气请求，
接口未提供的单项显示 `--`，过长内容省略，不编造默认指数。

1.11.1 修正三字指数被过早省略的问题：实际 20px 字库中 `: 较不宜` 需要
80px，原文字区只有 78px。现将文字区加宽到 88px、两列间距增至 120px，
卡片总宽增至 256px，字号、图标、右侧对齐及日期卡保持原样。
2026-11-14 用户已确认 1.11.0 日期卡显示正常、符合要求。

时钟下方使用一张日期卡片，公历以 28px 字体显示，中文星期（周日到周六）
紧随其右侧，公历数字与农历共用卡片中心线。下面依次显示农历、节气和节日，所有行均
居中；当天没有节气或节日时隐藏对应行，并将剩余内容在卡片中垂直居中。
日历每格显示公历日和农历日，
农历初一显示月份；点击日期后，下方显示农历、生肖，以及非空的节气、节日。
左右按钮或上下滑动切换月份，“今天”回到当前月份，侧边内滑返回桌面。

农历、生肖、节气、节日均在设备上离线生成，不调用心知农历或天聚数行接口，
无需新增 Key，不受接口七天范围限制。公历换算支持 **1901—2099 年**；
设备刚上电且尚未校时时会提示等待校时，沿用工程原有 WiFi 自动校时流程。
生肖以农历正月初一为界。节日涵盖常见公历节日、传统农历节日、母亲节和
父亲节；不包含国务院逐年发布的放假、调休和补班安排。

历法数据依据[香港天文台公历与农历日期对照表](https://www.hko.gov.hk/tc/gts/time/conversion.htm)，
把月首和每年二十四节气日期压缩到 Flash，共 14,624 字节的数值数据。
`LocalLunar.c` 根据公历天数查找月首，计算农历月日及生肖；除夕根据次日
是否为春节判断，同时兼容腊月二十九和三十。闰月不重复标注端午等传统节日。
换算不访问网络、SD 卡或系统时钟，也不分配堆内存。

`LifeData.cpp` 仅将[心知生活指数](https://docs.seniverse.com/api/life/suggestion.html)
放在独立短期任务中获取，沿用已有天气城市和 Key。结果按日期和城市校验，
当日成功后避免重复请求，并缓存到 SD 卡 `/.calendar/indices.json`（版本 2）。
旧版只有穿衣的缓存不作为新版四项缓存使用；新版本首次运行会重新请求。
请求失败或任务创建失败后至少等待五分钟重试；更换城市或日期变化会重新获取。
WiFi 未连接时不发起请求，界面在没有有效当日结果时显示 `--`。
网络、缓存损坏或内存分配失败不会影响本地农历和日历操作。

1.10.1 修复穿衣指数一直显示“待更新”：实测请求携带 `days=1` 时，
`suggestion` 变为带 `date` 的数组，原先仅支持对象格式的解析会拒绝该响应。
现默认使用不带 `days` 的基本指数请求，并兼容两种格式：对象按
`last_update` 校验当日，数组严格选取当前日期对应条目，不误用首条预报。
后台完成时只记录 ready/retry 和任务剩余栈，不打印 Key 或带 Key 的网址。

2026-11-14 用户已在 1.10.0 设备上确认主界面农历、日历的显示和操作正常；
穿衣指数当时未更新，按上述原因修复后需单独验证。

1.10.2 增加限频的后台状态日志，用于区分等待 WiFi、等待校时、缺少配置、
请求运行、失败退避和结果就绪，同时记录 AppServices 轮询是否完成。
实机已观察到 `waiting_wifi → starting → ready`，请求任务最小剩余栈为
3,276 字节，观察期间没有崩溃。2026-11-14 用户已确认 1.10.2 主界面的
穿衣指数正常显示；此前已确认的本地农历和日历交互继续保留。

## 文件与验证

- `src/LocalLunar.c/.h`、`src/LocalLunarData.inc`：本地换算和常见节日。
- `src/CalendarUI.c/.h`：带农历的月历、日期选择和详情卡。
- `src/LifeData.cpp/.h`：四项生活指数后台任务、当日缓存和 UI 读取接口。
- `src/HomeInfo.c/.h`：四个矢量图标、右上角指数卡和居中的日期卡。
- `src/ui/custom/custom.c`：主界面卡片创建与每秒刷新入口。
- `scripts/generate_local_lunar_data.py`：开发电脑下载原始年表并生成压缩数据；
  同时记录源文件 SHA-256、逐日参考结果，以及旧年表节气名称乱码的修复记录。
  修复仅按每月固定两个节气的顺序规范名称，沿用原表日期。

需要重建历法数据时，在开发电脑安装 Python `requests` 后执行：

```powershell
python scripts/generate_local_lunar_data.py
python tests/local_lunar_host_test.py
python tests/calendar_ui_host_test.py
python tests/desktop_ui_host_test.py
```

`local_lunar_host_test.py` 用实际 C 源码核对全部 72,684 个公历日期，检查闰月、
节气、生肖跨年、除夕、节日重合、非法日期和范围边界。两个界面测试使用
真实 LVGL 和工程 SD 字库，覆盖日期点击、滑动不误选、节日文本清除、跨年
翻月、侧边返回、重复打开、校时恢复和桌面原有触摸交互，并导出预览图片。

在 Visual Studio 开发者终端运行 `python tests/life_data_host_test.py`，
使用实际后台源码与真实 cJSON，验证断网、过期/异地缓存、请求中切换城市或
跨日、HTTP 错误、五分钟退避、任务/内存失败、响应长度、JSON 深度、UTF-8、
分块响应、不完整响应、超时，以及资源释放。这些主机测试无需真实账号或网络。
`tests/fixtures/seniverse_dressing_basic.json` 和 `seniverse_dressing_daily.json`
为 2026-11-14 实际响应提取的必要字段，不含 Key 或用户配置；测试同时覆盖
两种格式、预报列表中当日不是首条、没有当日条目、日期类型错误与缺失日期。
1.11.0 测试扩展到四项真实返回值、部分指数缺失、旧缓存迁移、完整四项缓存
读回，以及非法缓存字段；界面预览覆盖中文星期、普通日期、节气与节日同时
出现、节日重合、未校时/断网占位和长指数文本，并检查卡片与文字边界。

固件使用 ESP-IDF 5.5.6 构建；本次设备安装沿用活动 app1 分区，保留原有
分区、NVS、OTA 状态和 app0 回退固件。设备操作确认需在烧录后单独记录。

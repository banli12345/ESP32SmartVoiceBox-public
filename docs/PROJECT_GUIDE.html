PROJECT GUIDE / ESP32-S3 + LVGL 8.3.1

智能桌面终端项目文档

本项目是一个运行在 ESP32-S3 上的 480×480 LVGL 桌面终端，集成天气、时钟、日历、音乐、照片、视频、2048、陀螺仪平衡游戏、拼音输入和 AI 助手。大字体、图标、壁纸、拼音词典、音乐和视频放在 SD 卡，固件负责驱动、任务调度和应用逻辑。

ESP32-S3Arduino + PlatformIOLVGL 8.3.18 MB PSRAM16 MB Flash480×480 RGB
工程范围：v1.5 新增设备信息与文字浏览器，并包含设备端固件、资源转换与串口上传工具，以及从线上读取的 AI 服务器源码。后台源码和部署配置位于 server/；真实密钥和 PM2 私有环境转储仅保存在本机忽略目录。该备份随 v1.4 发布，尚未重新部署。从空机器重建和完整 AI 链路留作后续验证，目前仍未完成。
部署入口：当前版本为 v1.5（2026-10-08），新增设备信息和 HTTP/HTTPS 文字浏览器，继承串口素材上传、视频音频和 LRC 原样上传。main 与 v1.5 标签对应本次发布，旧版本标签保持不变。获取源码使用 git clone --branch v1.5。Git 源码不含 EXE 和 SD 素材；v1.5 Release 提供新固件包，上位机未修改，复用 v1.4 Release 的上位机包。平台配置、硬件接线和素材转换见 部署指南，浏览器用法见 文字浏览器，发布说明见 v1.5 发布说明。文字浏览器不能执行 JavaScript 或操作网页表单。

启动入口在 src/main.cpp 的 setup()。先恢复缓存、初始化 RGB 屏幕和 SD，再初始化触摸、LVGL、字体与壁纸缓存，创建 UI 并发布 SD 状态；随后初始化音频、AI、MPU6050 与 WiFi 服务，启动 LVGL 和传感器任务。

任务边界

任务/线程主要工作同步原则
LVGLTask每 5 ms 执行 lv_timer_handler()，处理页面切换、网络重连和 UI 更新。LVGL 对象只在该任务或 LVGL 回调上下文修改。
SensorTask每 20 ms 读取触摸；设备可用时读取 MPU6050。触摸和 MPU6050 共用 i2c_mutex。
MusicAudioTask读取 SD 上的 PCM WAV，控制播放、暂停、切歌、循环模式和闹铃。只有音频任务直接操作音乐 I2S 通道。
AIChatTask提交普通问答、天气和音量命令，接收服务器 JSON，再请求 Sound 播放 TTS。Sound 内的 ai_audio_mutex 防止同时播放两条 AI 语音。
AIWebSocketTask维持 /esp32 WebSocket 连接并处理服务器推送。音频通过 Sound 的 sound_ai_output_* 接口输出。

启动顺序

  1. 恢复时间、天气与壁纸选择，注册帧完成和 VSYNC 回调，初始化 RGB 面板并读取双帧缓冲地址。
  2. 释放 LCD 软件 SPI 与 SD 共用的引脚，挂载 SD_MMC 1-bit 模式。
  3. 配置背光、I2C 互斥与触摸；初始化 LVGL、SD 字体和壁纸缓存。
  4. 注册显示和输入设备，创建 UI、加载图标与词典，并发布 SD 状态。
  5. 初始化音频和 AI 任务、MPU6050 与 WiFi 服务。
  6. 启动 LVGL 和传感器任务；联网后同步北京时间并获取天气和三日预报。

模块说明

显示与 LVGL

main.cpp 创建 Arduino_ESP32RGBPanel 和 Arduino_RGB_Display。LVGL 使用 16 位颜色，屏幕尺寸为 480×480，RGB PCLK 为 10 MHz，DMA bounce 行数为 20。

SD_MMC 与 LVGL FS

GPIO48/47/41 连接 SD 时钟、命令和 D0，GPIO42 作为 DAT2/TF 控制线。挂载成功后通过 LVGL 文件系统字母 S: 访问资源。

字体加载

/fonts/chinese_16.bin、chinese_20.bin、chinese_32.bin 从 SD 加载；失败时 20px 字体回退到固件内置字体。

网络与缓存

setwifi.cpp 使用 Preferences 保存 WiFi、城市、天气和时间缓存。断网时仍显示最近一次有效天气和时钟。

传感器

MPU6050 使用加速度和陀螺仪融合计算 roll、pitch、yaw；UI 和平衡游戏使用相对角度，陀螺仪温度显示在主界面和陀螺仪页。

背光与音量

背光通过 LEDC PWM 控制；音量保存到 Preferences 的 audio/volume，PCM 输出按曲线缩放，低音量比线性缩放更安静。

设备端公开接口

这些接口在 custom.c 中通过 extern 使用，修改名字或参数时需要同步 C/C++ 声明：

music_audio_play();             // 播放或继续当前歌曲
music_audio_pause();            // 暂停并保留文件位置
music_audio_stop();              // 停止并关闭当前文件
music_select_track(index);       // 请求切换歌曲
set_music_play_mode(mode);       // 单曲、循环歌单、顺序歌单
ai_chat_submit(message);         // 提交 AI 问题
get_audio_volume();              // 读取音量
set_audio_volume(percent);       // 设置音量
start_photo_load(path);          // 异步读取照片
read_next_video_frame();         // 读取下一帧 RVF 视频

拼音键盘

键盘显示时，输入框点击/获得焦点会调用 show_text_keyboard()，候选栏放在键盘上方，避免遮挡第一排字母。主词典来自 SD 的 /ime/pinyin_full.txt；缺失时使用 custom.c 中的小型备用词典。

词典生成顺序是“常用简体字优先，再补充 GB2312 汉字”。脚本为单字母初始声母保留 a-z 行，并显式生成 h 行，解决“h 没有候选字”和“p 匹配到不合理字符”的问题。

音乐、闹铃与 AI 音频

音乐播放

音乐文件由 sdcar_scan_music_tracks() 扫描 /music 下的 WAV 文件。当前实现要求 PCM、双声道、16 bit WAV；歌词文件使用相同基础名的 .lrc。例如 晴天.wav 对应 晴天.lrc。

模式行为
单曲循环当前歌曲读完后从头打开同一文件。
循环歌单当前歌曲结束后切到下一首，最后一首回到第一首。
顺序播放歌单从当前歌曲播放到歌单最后一首后停止。

AI 语音与音乐互斥

音乐使用 I2S_NUM_0，AI 使用 I2S_NUM_1，两者共用 GPIO1（BCLK）、GPIO2（LRCLK）、GPIO40（DOUT）。AI 播放前，音乐任务写入静音并禁用 I2S0；AI 播放结束后禁用 I2S1，并通过 i2s_channel_reconfig_std_gpio() 将引脚路由恢复到 I2S0，然后恢复音乐任务。

音乐：SD WAV → Sound::MusicAudioTask → I2S0 → GPIO1/2/40
AI：HTTP WAV → Web_ai::play_ai_wav() → Sound::sound_ai_output_* → I2S1 → GPIO1/2/40
切换：暂停音乐 → 释放 I2S0 → 播放 AI → 关闭 I2S1
      → 恢复 I2S0 GPIO 路由 → 继续音乐
维护要点：不要在 UI 回调里直接启停 I2S。使用 music_audio_play/pause/stop()，让 MusicAudioTask 统一处理文件、静音、通道状态和切歌竞态。

AI 与服务器协议

普通问答 HTTP

设备端地址写在 src/Web_ai.cpp：http://YOUR_SERVER_HOST:3000/api/chat。请求为 JSON，当前只发送 message 字段。

POST /api/chat
Content-Type: application/json

{"message":"请回答用户的问题"}

期望的返回格式：

{
  "ok": true,
  "text": "回答文本",
  "audio_url": "http://服务器地址/生成的语音.wav"
}

audio_url 为空时只显示文字；有值时设备下载 WAV 并播放。TTS WAV 必须是 16 kHz、单声道、16 bit、PCM；设备会把单声道样本复制成双声道送入功放。

WebSocket 推送

设备通过 WebSocketsClient 连接 YOUR_SERVER_HOST:3000/esp32。服务器推送 JSON 类型为 ai_reply：

{
  "type": "ai_reply",
  "question": "用户原问题",
  "text": "回答文本",
  "audio_url": "http://服务器地址/生成的语音.wav"
}

设备收到后先识别本地音乐、音量和天气命令，再决定是否播放语音。音乐命令本地执行，因此“关闭音乐”“播放第二首”“下一首”等不依赖服务器意图识别。

天气服务

src/setwifi.cpp 调用心知天气：

GET http://api.seniverse.com/v3/weather/now.json
GET http://api.seniverse.com/v3/weather/daily.json?days=3

城市使用拼音请求，例如 nanning；设备通过本地城市表显示中文名。NTP 使用 ntp.aliyun.com、ntp.ntsc.ac.cn 和 pool.ntp.org，时区为 UTC+8。

服务器部署要求：服务器必须让设备可访问 API 和 WAV 文件 URL；如果 WAV URL 需要登录、HTTPS 证书链不受设备信任、响应不是 PCM WAV，设备端会显示文本但语音播放失败。server/server.mjs 使用 DeepSeek、edge-tts 和 FFmpeg 生成 16 kHz 单声道 PCM16 WAV，并在成功后向 /esp32 广播回复。健康检查为 GET /api/health；环境变量、实际部署配置和备份范围见 服务器说明。

显示、PSRAM 与防撕裂

RGB 屏幕持续由 DMA 扫描帧缓冲，LVGL 也会写入画面。如果两者同时访问同一块 PSRAM 帧缓冲，就会出现画面抖动、错乱或撕裂。

当前方案在 main.cpp 中获取 RGB 驱动的两个 framebuffer，注册 on_frame_buf_complete 回调，用帧完成计数等待 DMA 结束后再允许 LVGL 重用对应缓冲。my_disp_flush() 提交区域后等待下一次帧完成，避免 LVGL 覆盖正在扫描的内存。

LVGL 绘制 → 提交到空闲 framebuffer
RGB DMA 扫描 → 当前 framebuffer
帧完成回调 → 计数加一
LVGL flush 等待计数变化 → 才继续复用缓冲

照片和视频还使用额外的 PSRAM/缓冲策略：照片异步加载，视频先读下一帧到独立缓冲，再在 VSYNC 定时下更新图像。视频播放期间暂停 MPU6050 轮询，减少 I2C 和调度干扰。

内存诊断

启动日志中的 LVGL heap after fonts、LVGL heap after UI 和 PSRAM 行用于判断字体、图标和帧缓冲分配是否过量。大字体、图标和拼音字典优先放 PSRAM；失败时必须有明确回退或停止加载，不能继续解引用空指针。

资源转换脚本

资源转换脚本统一放在 scripts/。请在项目根目录执行命令，这样脚本能找到 font_assets/、当前字库和 sd_card_files/。生成的 BIN、TXT、RVF、WAV 都是 SD 卡资源，不会随固件编译写入 SD 卡。

日常素材可用中文图形上位机：双击项目根目录 SDMediaUploader.cmd，或 dist/SDMediaUploader/SDMediaUploader.exe。选择素材类型并添加 PNG/JPG、MP3/LRC 或 MP4，点击“转换并上传”。上位机自动生成对应 SD 文件，壁纸选择 1/2/3 位置，照片保比例转换成 480×450，视频默认 320×240、20 FPS 并同时提取音轨。未连接设备时可用“仅转换并导出”。

首次使用先烧录 v1.4 或更新接收固件，关闭其他串口监视器，再选择设备 USB 串口。设备以 115200 握手，重启进入专用上传模式，切到 921600 传输。16 KiB 分块带 CRC32 与应答重试，上传后从 SD 读回校验；整批完成才替换原文件，并重启加载缓存。每批最多 32 个输出文件，完整 SD 路径最多 63 个 UTF-8 字节。大视频受串口带宽限制，需要等待上传进度完成。打包程序需保留整个目录中的 _internal。

准备环境

  1. 安装 Python 3.9 或更新版本，然后安装脚本依赖：py -3 -m pip install -r scripts/requirements.txt。
  2. 字库脚本还需要源 simhei.ttf、对应的原有 BIN，以及 Node.js 24.21.0。Windows 版解压到 .tools/node-v24.21.0-win-x64/，确保其中有 node.exe 和 node_modules/npm/bin/npx-cli.js。这些文件不随 Git 提供；第一次运行会通过网络下载 lv_font_conv。
  3. 视频转换可使用系统 PATH 中的 ffmpeg；如果没有，已安装的 imageio-ffmpeg 会提供备用 FFmpeg。音轨探测只用这个 ffmpeg，不需要单独的 ffprobe。

脚本作用与输入输出
generate_pinyin_dict.pyfont_assets/common_3500.txt、Python pypinyin 和 GB2312 字符集；常用简体字排在候选前面。sd_card_files/ime/pinyin_full.txt
generate_gb2312_font.pysimhei.ttf、现有 20px 字库、common_3500.txt、Node.js 与 lv_font_conv。重建 sd_card_files/fonts/chinese_20.bin，补入 GB2312 汉字。
update_chinese20_font.py命令行文字或 UTF-8 文本文件；需要源 TTF、当前 20px BIN 和 Node.js。把新字符并入 sd_card_files/fonts/chinese_20.bin，原字形保留。
update_chinese32_city_font.pyfont_assets/city_names_32.txt、simhei.ttf 和现有 32px BIN。更新 sd_card_files/fonts/chinese_32.bin，保留原字形。
convert_app_icons.pyWebP/图片源；批量模式使用 --source-dir，目录内按脚本配置提供图标、壁纸和 图片/ 照片。LVGL alpha BIN：icons/、wallpapers/、imges/。
convert_video.pyMP4 或 FFmpeg 可读视频；可指定输出尺寸和帧率。默认提取主音轨。--no-audio 只写 RVF。--audio-only 给已有 RVF 补 WAV，不改画面。32 字节 RVF1 头的 RGB565 .rvf，以及同主文件名的 PCM16 .wav。默认写入 sd_card_files/videos/。源没有音轨时只留下 RVF。
shift_lrc.py带 [mm:ss.xx] 时间标签的 UTF-8 LRC，以及毫秒偏移。原地平移时间戳；正数让歌词提前，负数让歌词延后。

视频音轨

convert_video.py 默认把源视频的主音轨提取成和 RVF 同目录、同主文件名的 .wav。例如 /videos/ikun20.rvf 对应 /videos/ikun20.wav。WAV 固定为 44100 Hz、立体声、16 bit 有符号小端 PCM，block align 为 4，byte rate 为 176400。样本数是 RVF 时长 frame_count * 1000 / fps_milli 秒按四舍五入得到的采样帧数，循环时音画时长一致。提取时保留源音轨相对画面第一帧的时间戳，音轨晚于画面开始时，WAV 开头是静音，而不是把第一颗音频样本挪到 0。

源文件没有音轨时只生成 RVF。--no-audio 也只生成 RVF，并在新 RVF 写好后删除旁边的同名旧 WAV。--audio-only 先检查已有 RVF 的文件头和帧数据，再按其中的帧数和帧率生成 WAV，不重写画面。它不能和 --no-audio 同时使用。音轨提取失败时，原来的 RVF 保持不变。

设备播放同名 WAV 时，以 I2S DMA 已输出的样本作为播放时钟。画面来不及渲染时跳过过期视频帧，保持原视频的播放时长；320×240 源分辨率和现有缩放抗锯齿继续保留。WAV 单独预读到 48 KiB PSRAM 缓冲区，画面仍使用双缓冲 SD 预读。串口 [VIDEO] 的 presented_fps 是实际提交的视频帧率，主界面 FPS 是屏幕刷新率，两者含义不同。

打开视频会暂时占用音乐输出，退出后恢复此前播放的音乐。AI 语音和闹铃暂时接管输出时，视频音频时钟暂停，接管结束后从已输出的位置继续。没有 WAV、WAV 格式错误或时长不匹配时，设备记录 [VIDEO AUDIO] error 并继续无声播放；读取失败也会释放音频输出。停止时先等待预读任务完成当前 SD 操作，再关闭文件。

转换回归检查：py -3 -m unittest discover -s tests -p test_convert_video.py。固件的 WAV 文件校验与同步调度可在主机上编译 tests/wav_pcm_host_test.c 和 src/wav_pcm.c（头文件目录 src）后运行；包含截断文件、奇数块填充、采样时长取整、过期帧和循环边界检查。

部署生成结果

生成结束后，按输出路径把对应文件复制到 SD 卡根目录下的同名目录，例如 sd_card_files/fonts/chinese_20.bin 复制为 SD 卡的 /fonts/chinese_20.bin，sd_card_files/ime/pinyin_full.txt 复制为 /ime/pinyin_full.txt。图标、壁纸、照片和视频也遵循相同相对路径。视频要把同名 .rvf 和 .wav 一起复制到 SD 卡的 /videos；没有生成 WAV 时只复制 RVF。替换字库前先备份旧 BIN；更新 SD 资源后重启设备验证串口日志中的加载结果。

shift_lrc.py 会直接改写输入歌词，请先复制备份。字体转换会先写入临时 .new 文件，通过校验后再替换原 BIN。

编译、烧录与部署

1. 编译环境

项目使用 PlatformIO 的 esp32-s3-devkitc-1 环境和 LVGL 8.3.1。本机已验证 pioarduino 55.03.312、Arduino-ESP32 3.3.12 与 ESP-IDF 5.5.5；仓库平台来源尚未锁定，新电脑请先按 编译环境指南 配置。platformio.ini 已指定 16 MB Flash、OPI PSRAM、DIO Flash 模式、240 MHz CPU 和 921600 上传速率。

# 从项目根目录执行
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run

# 清理后全量编译
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run -t clean
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run

# 编译并上传
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run -t upload

# 115200 波特率监视器
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" device monitor -b 115200

开发中遇到的问题与处理

现象原因当前处理
点击输入框没有键盘LVGL textarea 没有正确获得焦点，键盘显示状态也没有随事件处理。监听点击、按下和聚焦事件；统一调用 show_text_keyboard()，候选栏位于键盘上方。
候选字生僻、拼音不匹配、h 没字词典顺序不合理，LVGL K26 对单字母初始输入需要对应行。常用 3500 字优先，补全 GB2312，生成 h 行和 a-z 对齐行。
大字库加载后 Guru Meditation字体、图标、拼音索引和 LVGL 缓冲挤占内部堆，空指针继续使用。优先从 PSRAM 分配，加载后验证字形，失败回退；串口打印 LVGL/PSRAM 空间。
RGB 屏幕抖动或撕裂LVGL 写入 DMA 正在扫描的同一帧缓冲。双 framebuffer、帧完成回调、flush 等待 DMA 帧边界；视频使用独立帧缓冲。
音乐播放一段时间后停声播放/暂停/切歌线程同时操作 I2S，停止清理和下一次播放发生竞态。由 MusicAudioTask 独占 I2S；播放请求用临界区保存，停止时写静音再禁用通道。
AI 语音后音乐无声AI I2S1 把 GPIO1/2/40 路由走后，关闭 I2S1 没有恢复 I2S0 路由。AI 前禁用音乐通道，AI 后重配置音乐 GPIO，再恢复音乐。
音量调低仍然很响线性缩放在低百分比下听感不够安静。使用幂函数曲线，低档位衰减更明显；音量保存到 Preferences。
关闭音乐后再次播放无声停止标志、播放标志和 I2S 通道清理顺序不一致。播放请求保留到清理结束，任务完成静音和 disable 后再重新唤醒。
WiFi 恢复后天气不更新旧逻辑只在 setup 阶段获取天气。LVGLTask 检测断开到连接的边沿，重新同步 NTP、当前天气和预报。
视频播放时画面错乱SD 读取和 RGB DMA 同时修改图像源，I2C 传感器轮询也增加调度压力。下一帧先读入独立缓冲，按 VSYNC 更新；视频期间暂停 MPU6050 读取。
歌词显示提前或滞后LRC 时间戳与音频实际起点不一致。使用 shift_lrc.py 平移时间，设备也支持 LRC [offset:]。

SD、字体、图标、拼音、RGB 双缓冲和 Setup complete 日志正常。

输入

AI 输入框能弹键盘；a-z、h、常用拼音和候选词均可输入。
